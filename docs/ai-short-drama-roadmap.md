# AI 短剧制片系统研究路线图

状态：研究与架构规划，尚未作为当前可用能力发布。

更新日期：2026-08-12

## 产品目标

用户只输入一个主题，也可以进一步指定类型、受众、风格、集数、每集时长、画幅和质量。系统随后生成并允许用户审阅：

1. 系列设定与总故事弧。
2. 角色、服装、道具和场景资产圣经。
3. 每集梗概、冲突、钩子与结尾悬念。
4. 逐场剧本、对白、动作和声音设计。
5. 逐镜头分镜、时长、机位、参考素材和 H3 生成参数。
6. 通过本机门禁的 ComfyUI 任务队列、失败镜头重试与最终装配计划。

“一键生成”不是绕过审核。只有资产已经锁定、试播集通过、模型与显存门禁通过后，系统才允许批量生成整季。

## 用户可配置输入

| 分类 | 参数 |
| --- | --- |
| 故事 | 主题、类型、时代、世界观、核心冲突、受众、内容尺度、语言、结局倾向 |
| 系列 | 集数、每集目标时长、单集结构、连续剧 / 单元剧、每集钩子与悬念强度 |
| 视觉 | 真人 / 动画 / 风格化、画幅、色彩、摄影语言、发布平台、目标质量 |
| 角色 | 主要角色数量、年龄边界、关系、性格、说话方式、可上传角色参考图 |
| 声音 | 对白 / 旁白比例、语言、声音参考、环境声、音乐策略、字幕需求 |
| 执行 | 只写剧本、生成故事板、试播集、整季生成、自动 / 人工确认点 |

系统必须在正式规划前估算总镜头数、预计生成块数、磁盘占用和大致排队规模，并允许用户缩短集数、时长或质量。估算不能伪装成精确完成时间。

## 核心数据模型

所有中间产物必须是可验证、可版本化的结构化数据，而不是只存在于一段长对话中。

| 实体 | 关键字段 |
| --- | --- |
| `SeriesProject` | 项目 ID、主题、集数、每集时长、画幅、质量、语言、状态、版本 |
| `SeriesBible` | 世界规则、总故事弧、人物关系、视觉规则、声音规则、禁止变化项 |
| `CharacterAsset` | 角色 ID、身份特征、体型、发型、声音 ID、表演规则、参考素材 |
| `WardrobeState` | 服装 ID、适用角色、服装细节、配饰、开始 / 结束集与场景、污损状态 |
| `PropAsset` | 道具 ID、外观、所有者、位置、状态变化和连续性规则 |
| `LocationAsset` | 场景 ID、布局、时代、时间、天气、光线、锚点图和可用机位 |
| `EpisodePlan` | 集标题、剧情目标、冲突、转折、结尾钩子、角色状态变化 |
| `ScenePlan` | 场景目标、地点、时间、出场角色、服装、道具、前后状态 |
| `ShotPlan` | 镜头 ID、时长、景别、机位、运动、动作、对白、声音、引用资产、生成参数 |
| `GenerationRecord` | 模型 / 节点版本、工作流版本、seed、输入引用、输出、耗时、错误和重试来源 |
| `ContinuityIssue` | 问题类型、证据镜头、严重级别、建议修复、是否需要重生成 |

每个镜头只能引用明确的角色、服装、道具和场景 ID。角色换装、道具损坏、昼夜变化等必须通过显式状态迁移发生，不能让模型自行猜测。

## 分层制片工作流

```text
主题与参数
  → 系列圣经
  → 角色 / 服装 / 道具 / 场景资产
  → 分集大纲
  → 逐场剧本与对白
  → 逐镜头摄影脚本
  → 故事板关键帧
  → H3 镜头提示词与引用编译
  → 试播集门禁
  → 整季队列
  → 连续性检查与单镜头返修
  → 配音 / 字幕 / 声音 / 成片装配
```

建议使用职责隔离的规划器，而不是让一个模型同时决定所有内容：

- 制片规划器：约束集数、时长、镜头预算和硬件成本。
- 编剧：生成系列弧、分集、场景、动作和对白。
- 角色监督：检查人物动机、语气和关系是否符合角色圣经。
- 美术连续性监督：锁定服装、道具、地点、天气、光线和状态迁移。
- 摄影指导：把场景拆成镜头，决定景别、机位、运动、视线与轴线。
- H3 编译器：把镜头结构编译为官方 Base / I2VA / Ref2VA 提示结构。
- 连续性检查器：比较相邻镜头与跨集资产状态，只重试失败镜头。

每一层都要输出 JSON Schema 可验证的结果；导演审阅层负责 Critique → Correct → Verify，而不是把多个代理的自由文本直接串联。

## 一致性策略

### 角色

- 先生成或导入角色定妆资产，再允许生成正片。
- 每个角色建立正面、侧面、全身、表情和声音参考，引用时保持固定角色 ID。
- 多角色镜头必须明确 Subject 与 Picture 的一一映射；Ref2VA 多图模式只能在本机真实工作流通过后开放。

### 服装与道具

- 服装按剧情区间绑定，例如 `WARDROBE_A_EP01_SC01-SC04`。
- 道具记录所有者、所在位置、完好 / 损坏 / 消失等状态；剧本和镜头计划都必须通过状态检查。
- 一致性不能只依赖重复提示词，应同时使用参考图、结构化状态和生成记录。

### 场景与摄影

- 每个主要地点建立场景锚点图、布局、光线和时间状态。
- 镜头计划记录角色位置、视线方向、屏幕方向和相邻镜头关系。
- 场景切换用明确的建立镜头或转场，不让模型自动补全空间关系。

### 声音

- 角色声音、对白文本、情绪、环境声和音乐分别建模。
- 镜头时长必须容纳对白；超长对白应改写或拆镜，不能依赖后期强行加速。
- 保存语音模型、参考音频和字幕版本，支持仅重做音频而不重生成画面。

## H3 与 ComfyUI 的执行边界

- MiniMax H3 FL2VA 官方支持无图、首帧、尾帧和首尾帧条件；Ref2VA 支持图像、视频和音频参考。当前 H3 Flow 只开放已经在本机验证的子集。
- 单镜头优先使用短、安全的 H3 片段。跨镜头一致性依赖资产引用、首尾帧、局部剧情隔离和生成记录，不宣称一次模型调用即可完成整集。
- ComfyUI 子图适合把角色关键帧、镜头生成、放大、声音、字幕和装配封装为可复用模块；正式提交仍需逐任务 schema、模型、版本、队列和显存门禁。
- 本机 16GB 显存默认串行生成。整季任务必须支持暂停、恢复、跳过、取消未开始镜头和失败镜头单独重试，不能因为一个镜头失败而重跑整集。

## 产品模式

1. **只写剧本**：输出系列圣经、详细分集、逐场剧本和对白，不调用 ComfyUI。
2. **故事板**：生成或导入角色 / 场景资产，并产出逐镜头关键帧和摄影脚本。
3. **试播集**：只生成一集或若干代表镜头，验证角色、服装、场景、声音和硬件方案。
4. **整季生成**：只有试播门禁通过后才开放；按镜头排队并持续运行连续性检查。

“一键”按钮应显示将要生成的集数、镜头数、参考素材、质量、风险与本机资源计划，用户确认后才开始。

## 验收门禁

- 结构门禁：每集总时长、场景和镜头时长可计算且无缺失引用。
- 剧情门禁：角色动机、前后状态、铺垫、冲突、转折和结尾钩子不存在明显矛盾。
- 资产门禁：所有角色、服装、道具和地点 ID 都能解析到锁定资产。
- 摄影门禁：动作、对白、机位、视线、轴线和相邻镜头衔接可执行。
- 生成门禁：模型、节点、版本、显存、系统提交空间、磁盘和队列通过。
- 画面门禁：角色身份、服装、道具、场景和镜头边界经过自动评分与人工抽检。
- 声音门禁：对白时长、说话人、字幕、响度和声画同步通过。
- 恢复门禁：任何失败都能定位到项目 / 集 / 场 / 镜头，不丢失已通过产物。

自动评分只能用于发现风险，不能直接宣称角色或剧情已经完全一致。最终发布仍需人工检查试播集与高风险镜头。

## 分阶段开发

### P0：结构化制片规划器

- 主题 → 系列圣经 → 分集 → 场景 → 镜头 JSON。
- 支持自定义集数、每集时长和只写剧本模式。
- 完成 Schema、版本迁移、编辑、重新生成单层和导出，不生成视频。

### P1：资产圣经

- 角色、服装、道具、场景管理和状态时间线。
- 参考图上传、标签、引用冲突检查和资产锁定。
- 多图 Ref2VA 在真实 schema、显存和成片门禁通过后开放。

### P2：试播集

- 镜头故事板、H3 编译、串行队列、断点恢复和单镜头重试。
- 先实跑少量镜头与一集，建立人物、服装、场景、声音和接缝基线。

### P3：整季与返修

- 批量排队、暂停 / 恢复、版本追踪、失败隔离、替换镜头和重新装配。
- 连续性问题面板按集、场、镜头显示证据和修复范围。

### P4：受控一键制片

- 用户选择主题和参数后自动完成规划；在资产批准和试播通过后执行整季。
- 提供剧本、分镜表、资产包、工作流、字幕、音频和成片清单。
- 在真实多集测试没有通过前，不标记为“稳定一键生成短剧”。

## 本地数据与隐私

- 每个短剧使用独立本机项目目录，保存相对路径、版本化 JSON 和生成记录。
- API Key 不写入项目；参考图、声音和生成媒体不进入 Git。
- 公共日志和导出包必须清除用户名、绝对路径、凭据和个人媒体元数据。
- 不自动安装第三方节点或下载未知模型；所有执行组件继续受兼容性清单约束。

## 研究依据

- [MiniMax H3 官方仓库](https://github.com/MiniMax-AI/MiniMax-H3)：FL2VA、Ref2VA、多模态参考和原生声画能力边界。
- [MiniMax 视频生成官方文档](https://platform.minimax.io/docs/guides/video-generation)：首帧、尾帧和首尾帧 API 条件。
- [ComfyUI Subgraph 官方文档](https://docs.comfy.org/interface/features/subgraph)：复杂工作流模块化与复用。
- [LTX Studio 官方产品页](https://website.ltx.studio/)：从概念 / 剧本到场景和故事板的产品路径。
- [MovieAgent](https://arxiv.org/abs/2503.07314)：角色库、分层规划和多代理电影制片。
- [FilmAgent](https://arxiv.org/abs/2501.12909)：创意、剧本、摄影分阶段，以及 Critique-Correct-Verify / Debate-Judge。
- [StoryDiffusion](https://arxiv.org/abs/2405.01434)：跨画面主体一致性和长程故事可视化研究。
- [StreamingT2V](https://arxiv.org/abs/2403.14773)：短期运动记忆与长期外观保持的长视频研究。

这些案例提供架构参考，不代表其代码、模型或能力已经集成到 H3 Flow。
